## Confirmed Guide Claims

- The repo layout in the guide matches the source tree.
- The main window is owned by `MainWindowController`; `CadenceApp` declares the menu-bar extra and Settings scene, not a competing main `WindowGroup`.
- `AppModel` is still the central observable orchestrator for permissions, dictation, meetings, calendar, windows, settings, and persistence.
- Dictation and meeting capture are separate flows. Dictation uses microphone capture, `DictationCoordinator`, `WhisperKitTranscriptionEngine`, and `TextInsertionService`; it does not depend on meeting-note storage.
- Meeting capture uses `recordingID`, live draft segments, saved CAF audio, and a final pass from `MeetingFinalTranscriptionService`.
- Replacement rules are enforced in source: live draft segments are tagged `.liveDraft`, final segments are tagged `.final`, and `MeetingNote.replaceLiveDraftSegments(recordingID:with:)` removes only live draft segments for the matching recording.
- Empty final output is failure, not replacement: `AppModel.runFinalTranscriptionPass` throws `WhisperEngineError.noTranscript` when the final segment list is empty.
- System audio capture is separate from microphone capture and uses ScreenCaptureKit.
- Google Calendar is split between OAuth/API work in `GoogleCalendarService`, pure prompt selection in `MeetingDetectionService`, and UI/AppModel coordination.
- Meeting notes persist as JSON through `MeetingStore`; meeting audio persists as CAF through `MeetingAudioStore`; Google tokens persist in Keychain.
- The build script supports the improvement-plan definition of done: `--verify`, `--test`, and `--audio-smoke` exist.

## Drift Found

### Permission Model Was Too Compressed In The Guide

The guide said the permission wizard handles macOS permissions, but source shows a split:

- `PermissionsSnapshot` tracks Microphone, Accessibility, Input Monitoring, and Screen Recording.
- `PermissionsSnapshot.allRequiredGranted` covers only Microphone, Accessibility, and Input Monitoring.
- `PermissionGuideWindow` and the Settings setup row list only those three dictation permissions.
- Screen Recording is requested contextually by meeting capture when the selected source requires system audio.

Correction made: `docs/codebase-guide.md` now has a dedicated Permissions Model section explaining this split.

Plan impact:

- R3 should not assume the current first-run wizard already covers all four permissions.
- U4 remains necessary because Screen Recording remediation is contextual, not fully first-run.
- R7 should update user-facing privacy copy so Screen Recording is described for system audio capture.

### Release Packaging Exists But Is Not Proven Release-Ready

The plan treats R1 as if the signing/notarization pipeline needs to be built. Source shows `scripts/package_release.sh` already archives Release, exports Developer ID, creates a DMG, submits to notarytool, staples, and runs Gatekeeper assessment. It also supports `--skip-notarization`.

Correction made: `docs/codebase-guide.md` now describes the release script behavior and human prerequisites.

Plan impact:

- R1 is partly implemented. The remaining work is credentialed validation, clean-machine launch proof, entitlement/Info.plist/TCC audit, and any fixes found during that validation.
- The human gate remains unchanged: Developer ID certificate and notary credentials are still required.

### Crash Recovery Is Partial

The guide correctly says saved audio is durable before final transcription, but it did not spell out the current recovery boundary:

- Audio chunks are written to CAF during recording.
- Recording metadata is appended to the note only after stop.
- `recoverInterruptedFinalizations` can mark interrupted live/finalizing notes as retryable only when audio recording metadata already exists.
- A force-quit during active recording may leave a CAF file that is not discoverable from the note because metadata was not persisted incrementally.

Correction made: `docs/codebase-guide.md` now flags this as a current design risk.

Plan impact:

- R4 remains valid and should specifically implement incremental recording metadata or another discoverability mechanism for active-recording crash recovery.
- U3's recovery UI depends on R4 for the force-quit-mid-recording case.

### Export/Summary Duplicate Collapse Is Less Strict Than The UI Path

`AppModel.shouldMergeAdjacentTranscript` and `MeetingNotesWindow.TranscriptRun` include segment origin and recording ID in merge checks. `MeetingSummaryService` and `MeetingMarkdownFormatter` collapse adjacent duplicate transcript text using text, speaker, and capture source only.

Correction made: `docs/codebase-guide.md` now flags this as a current design risk.

Plan impact:

- T2 should include export/summary duplicate-collapse invariants, not only the note replacement rule.

### Build Script Flag List Was Incomplete

The guide omitted `./script/build_and_run.sh --debug`.

Correction made: the flag list now includes `--debug`.

## Drift Not Corrected In This Pass

These are outside A0's "correct the guide" scope but should be picked up by later tasks:

- `docs/privacy.md` and `docs/release-checklist.md` describe Microphone, Accessibility, and Input Monitoring, but do not mention Screen Recording for system audio capture.
- `MeetingStore` has no `schemaVersion`, migration runner, fixture corpus, or quarantine path yet. This confirms R6 is still needed.
- `AppModel` still directly owns UserDefaults, capture services, stores, calendar polling, and window controllers. This confirms H1 to H4 are still needed.
- `GoogleCalendarService` uses a custom redirect scheme derived from the OAuth client ID; release validation should confirm the app bundle registers or otherwise supports the callback path expected by `ASWebAuthenticationSession`.

## Invalidated Plan Tasks

No task is invalidated by source drift.

Adjusted task interpretation:

- R1 is not greenfield; treat it as pipeline validation and hardening.
- R3/R7 must include Screen Recording copy and user-visible remediation for meeting capture.
- R4 remains the required fix for active-recording crash recovery.
- T2 should include export/summary merge behavior in addition to model replacement behavior.
